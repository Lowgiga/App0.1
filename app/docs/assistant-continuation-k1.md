# K1: saved personal drafts in contextual continuation

Internal review change on source f57200cd8e13f840f2bffb12ffc43d2ace1dcab3dc4a8abaab67b17721588429. No prototype release or Quality adoption.

The Assistant reads the existing personal-continuation endpoint. A collection compares two config reads and two personal reads, including the complete personal response, and checks local WorkState before and after. Each personal read is an existing read-only local transaction. This is a revision-checked collection, not an atomic multi-endpoint snapshot. Every advice, preview, review, commit precheck and deliberate Memory navigation recollects the basis. A draft-only change therefore invalidates the old advice even when WorkState and Memory revisions are unchanged.

Personal drafts have no individual UUID. There is one draft slot per contextId + contextCreatedAt; its revision increases across save, discard and application. The existing advisory `kind: draft` reference uses the context UUID as a **derived slot reference**, with the containing envelope's incarnation and the saved draft revision. It is not a newly persisted draft ID. Only active draft metadata crosses the advisory boundary. Composer text never enters the Assistant snapshot, summary, adapter input or event log. Applied and discarded drafts remain distinct in host-only presentation, without an active advisory reference. Confirmed next steps come only from actual confirmed Memory entries, including entry ID and revision.

The continuation card identifies the project, saved revision, time and kind, marks an outdated Work/Memory basis, and states the unconfirmed boundary. It respects the existing continuation-enabled setting. It never displays an unsaved composer as saved data. A failed or inconsistent read is not presented as absence of a draft.

`openMemory` discards advisory results and config previews, rechecks the complete collected basis, and invokes a host-only navigation callback under the session generation guard. The panel also checks that the URL has not changed. Navigation uses the canonical existing context URL. It does not remember a start point, open a draft, rebase it, apply it, confirm Memory or change config. The mounted Memory editor retains its existing flush, conflict and explicit-abandonment behavior. A hidden dirty editor may attempt its already authorized autosave on navigation; that write belongs to the existing editor, not the Assistant. Failed flushes retain text and require the existing user decision.

The preview → review → explicit commit → independently read receipt boundary is unchanged. No new endpoint, database, provider, engine, token, permission or backup field is introduced. There is no continuous polling or guarantee against a new write after the final read: a later operation rechecks the basis, and the Memory editor performs its own CAS checks.

Regression coverage includes draft scope and text exclusion, active/none/discarded/applied states, stale bases, two-read collection races, in-flight advice, CAS winners/losers, invalid foreign responses, storage errors, navigation conflicts, deactivation, exact destination and preservation of a conflicted hidden editor. Browser evidence and full verification logs are maintained separately from accepted Quality metadata for independent review.
