# Native Android handoff design (not implemented here)

The parent owns the separate native wrapper. The portability task does not generate or sign an APK and does not accept SDK licenses or modify the native toolchain.

## Version-locked initial proposal

Proposed compatible baseline for review: `@capacitor/core = 8.0.0`, `@capacitor/android = 8.0.0`, `@capacitor/cli = 8.0.0`. Keep all three at the same exact reviewed version and commit the resulting lockfile. This is an explicit baseline proposal, not a claim that it is the latest 8.x patch; the wrapper builder may choose a newer reviewed matching 8.x version and document that pin.

Capacitor's 8.0 upgrade documentation specifies Node 22+, compile/target SDK 36, minimum SDK 24, AGP 8.13.0, Gradle 8.14.3 and Android Studio Otter 2025.2.1+ for IDE workflows. The parent-provided JDK 21/SDK 36 toolchain remains separate. Use the exact native template generated by the selected release rather than mixing arbitrary version constants. Source: [official Capacitor 8 upgrade guide](https://capacitorjs.com/docs/updating/8-0), checked 2026-09-30.

## Proposed configuration, to verify against installed types

```json
{
  "appId": "APP_ID_CHOSEN_BY_PARENT_AND_KEPT_STABLE",
  "appName": "Cue Command Mesh",
  "webDir": "dist",
  "loggingBehavior": "debug",
  "server": {
    "hostname": "localhost",
    "androidScheme": "https",
    "cleartext": false
  },
  "android": {
    "allowMixedContent": false,
    "webContentsDebuggingEnabled": false
  }
}
```

The native task chooses the real application ID before first install and preserves it. Do not use an external `server.url`, wildcard navigation, native HTTP interception, private Site cookies, fake user headers or copied credentials. Keep the static content packaged inside the app. Verify the config against the selected package's actual types and [official configuration documentation](https://capacitorjs.com/docs/config).

## Data retention invariants

1. Preserve application ID, app signing continuity, origin scheme/hostname, database name `cue-command-mesh-local`, database version and record key.
2. Never call `deleteDatabase`, `clearData`, `clearCache` as a migration, or replace a corrupt stored state with `emptyWork`.
3. Update `versionCode` monotonically; test install-over-update without uninstalling. Persist a note, changed setting, mission, action/event and imported record; update the APK; compare complete exported work before/after, ignoring only expected metadata.
4. Explicitly test process death, app restart, offline cold start, low-storage failure and interrupted saves. Current Node tests do not establish these device outcomes.
5. No cloud synchronization, Android backup, recovery or storage-eviction guarantee is implied. Privacy handling for OS backup must be decided and verified in the native wrapper, not silently assumed.

## Release blockers

- Review all private bundled assets and avoid release logs exposing work content.
- Implement/verify Blob downloads, file picker/JSON import, clipboard and external-link handling. Add explicit injected platform adapters if the stock WebView does not preserve behavior; do not intercept global APIs silently.
- Verify navigation/hardware Back, keyboard focus/resize, cutouts/system bars, large text and accessible touch targets.
- AR is unverified. Retain real runtime capability checks and 3D/flat fallback. Do not use `android:use32bitAbi=true` or claim Chrome WebXR parity for Android WebView.
- The browser candidate's CSP uses `connect-src 'none'`. Native bridge behavior must be verified in the packaged app; do not broadly remove CSP to make hidden requests work.
- Full MCP/remote service transport remains missing. Implement only through a separately reviewed authorized architecture; a static status screen does not satisfy connectivity.
- Final Sites V5/App 1.4 source is imported in this port; copy only the new manifest-matched build into the native wrapper. The V4 overlay fixes are unchanged.
- V5 AR now requires a usable DOM overlay and includes session-end restoration/recentering controls; do not transfer older V4 AR defect assumptions to it. Real Android WebXR capability and lifecycle testing are still mandatory.
