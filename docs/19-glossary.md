# Glossar

| Begriff | Bedeutung in LowQuantFlow |
| --- | --- |
| WorkState | Gemeinsamer fachlicher Zustand von Aufgaben, Missionen, Quellenbezügen, Räumen, Einstellungen und Lernen |
| CAS | Compare-and-swap: Schreiben nur gegen die erwartete unveränderte Revision |
| Revision | Versions-/Zeitkennzeichen eines konkreten gespeicherten Zustands, kein Qualitätswert |
| Upstream | Gepinnte ursprüngliche V7-Webquelle |
| Overlay | Explizit erzeugte begrenzte Integrationsänderung an vorhandenen Modulen |
| Provenienz | Nachvollziehbare Herkunft von Quelle, Daten und Änderungen |
| Kandidat | Exakte vorbereitete Quelle, die noch nicht vollständig ausgeliefert/abgenommen ist |
| Freeze | Abgegrenzter unveränderlicher Prüfcheckpoint; keine automatische APKfreigabe |
| Skill | Manifest- und ressourcenbasierte begrenzte Funktion; hier vier echte Offlinehandler |
| Workflow | Geordneter begrenzter lokaler Prüfplan |
| Journal | Validierter operativer Fortsetzungszustand im Recovery-Kandidaten |
| Historischer Verlauf | Dokumentierte frühere Ergebnisse ohne neue Resume-Autorität |
| ACK / Readback | Bestätigte Commitantwort und anschließende Prüfung des gespeicherten Zustands |
| Shadow | Geplante Simulation auf getrennter Kopie ohne operative Außenwirkung |
| Impact / Wirkungsanalyse | Geplante Ableitung betroffener Objekte und Prüfungen aus bekannten Beziehungen |
| Projektgedächtnis | Geplante projektisolierte Herkunfts-/Entscheidungs-/Revisionshaltung |
| Provider | Externer Dienst; ein Katalogeintrag ist keine aktive Verbindung |
| Hologramm | Bildschirmstil, kein physisches Hologramm |
| AR | Kamera-/Raumbezug über unterstützten WebXR- oder nativen ARCore-Pfad |
| Next | Getrennte zukünftige Android-Appidentität neben Preview |
| Signierung | Kryptografische APKidentität; unabhängig von der sichtbaren Produktmarke |
| Restore | Wiederherstellung gespeicherter Daten; aktuell kein produktiver Vollrestore |
| Gate | Vor einer bezeichneten Freigabe erforderlicher überprüfbarer Nachweis |
